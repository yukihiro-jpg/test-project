# 銀行CSV修正ツール 仕様書

## 1. 製品概要

### 1.1 目的
会計事務所の顧問先向けに、銀行からダウンロードしたCSV（通帳明細）の **摘要欄を効率的に補完・修正** し、会計ソフトに取込可能な状態へ整える Windows デスクトップアプリ。

### 1.2 ターゲット利用者
- 会計事務所の顧問先（一般企業の経理担当者）
- 1顧問先 = 1インストールで配布。アプリ内に **複数顧問先のデータが混在することはない**

### 1.3 配布形態
- Windows 向け msi または exe インストーラ
- 顧問先ごとに個別配布
- 暗号化なし（ローカルファイルとして素直に保存）

## 2. 機能仕様

### 2.1 CSV取込

#### 2.1.1 取込方式
**列マッピング方式** を採用する。事前定義された銀行リストには依存しない。

- 初回取込時、ユーザーが「この列が日付」「この列が摘要」とマッピングUIで指定
- 銀行ごとのマッピングを **テンプレートとして学習** し、次回同じ銀行のCSVは自動認識
- 銀行識別はCSVのヘッダー行のシグネチャ（列名のハッシュ）等で判定

#### 2.1.2 金額列の表現
銀行によって金額列の構造が異なるため、両方を許容:

- **1列方式**: 金額列1つで、正負により入金/出金を表現
- **2列方式**: 入金列・出金列が別々

マッピング画面で切替可能。

#### 2.1.3 文字コード
- Shift_JIS / UTF-8 / UTF-8 BOM の自動判定

#### 2.1.4 取込単位
- 1ファイルずつ（複数同時タブは不要）

#### 2.1.5 元CSVの保管
- 取込時にアプリ管理下のフォルダへ **元CSVをそのままコピー保存**
- アプリ内に **「元CSVを開く」ボタン** を配置し、押下でモーダル内にテキスト表示

### 2.2 未処理検出ルール
- **摘要列が空欄の行のみ** を「未処理」とする
- それ以外の項目（金額・日付など）の不整合は検出対象外

### 2.3 編集UI

#### 2.3.1 画面レイアウト（左右2ペイン）

```
┌──────────────────────────┬──────────────────────────┐
│ 左ペイン                  │ 右ペイン                  │
│ 元CSV（読み取り専用）     │ 解析データ（編集可能）    │
│                          │                          │
│ ・元の列順そのまま        │ ・列マッピング適用後      │
│ ・行番号付き              │ ・空欄行をハイライト      │
│ ・スクロール              │ ・上部に ← / → ナビボタン │
│                          │                          │
└──────────────────────────┴──────────────────────────┘
```

#### 2.3.2 ペイン連動
- **スクロール連動**: どちらか一方をスクロールすると反対側も追従
- **選択連動**: 行をクリックすると反対側も同じ行をハイライト

#### 2.3.3 編集制約
- **摘要列のみ編集可能**
- 日付・金額・残高など他列は読み取り専用

#### 2.3.4 表示形式
- Excel風グリッド（TanStack Table）
- **全件表示**（仮想スクロールでパフォーマンス確保）
- 未入力行は背景色でハイライト

### 2.4 ナビゲーション

右ペイン上部に以下を常設:

- **← ボタン**: 「前の未処理行へジャンプ」
- **→ ボタン**: 「次の未処理行へジャンプ」
- **残件バッジ**: 例「未処理 12件」

### 2.5 取引先自動学習

#### 2.5.1 学習キー
- **金額 ＋ 日付パターン** で取引を識別
- 例: 「毎月25日に同額の引き落とし → 同一の取引先」と推定

#### 2.5.2 動作
- 過去に入力された摘要を学習履歴として保存
- 編集時にマッチした履歴を候補としてサジェスト
- ワンクリックで適用可能

#### 2.5.3 学習データの永続化
- ローカル SQLite に保存
- 1顧問先 = 1データベースとして扱う（顧問先分離処理は不要）

### 2.6 途中保存

- 編集中の内容は **任意のタイミングで途中保存可能**
- アプリを閉じても再起動後に作業を再開できる
- 保存先は SQLite

### 2.7 エクスポート

#### 2.7.1 出力ファイル名
```
{銀行名}_{口座名}_{開始日}_{終了日}.csv
```
例: `三井住友銀行_本店営業部_20251101_20251130.csv`

#### 2.7.2 出力先
- 元CSVとは別ファイルとして出力（上書きしない）

#### 2.7.3 未処理行が残った状態でのエクスポート
- **警告ダイアログを表示し、OKを押せば強行可能**
- ダイアログ例: 「未処理行が 12件 残っています。このまま出力しますか？」

## 3. データモデル

```
bank_template         銀行マッピングテンプレ
├── id
├── name              （例: 三井住友銀行、ゆうちょ等。ユーザー命名）
├── header_signature  ヘッダー行のハッシュ
├── column_map        JSON: {date: 0, summary: 2, amount: 3, ...}
└── amount_style      "single" | "split"

import_session        途中保存セッション
├── id
├── bank_template_id
├── account_name
├── period_from
├── period_to
├── source_path       元CSVの保管パス
├── status            "in_progress" | "completed"
└── updated_at

transaction_row       作業中の各行
├── id
├── session_id
├── row_index
├── date
├── original_summary
├── edited_summary
├── amount
├── balance
└── needs_review

counterparty_history  取引先学習履歴
├── id
├── amount
├── day_of_month
├── summary
├── hit_count
└── last_used_at
```

## 4. 技術スタック

| 層 | 採用技術 | 採用理由 |
|---|---|---|
| アプリ基盤 | Tauri 2 + React + TypeScript | Windows向けexe/msi生成、軽量、表計算UIが組みやすい |
| 表UI | TanStack Table + 仮想化 | Excel風グリッドの定番、数万行でも軽量 |
| ローカルDB | SQLite (tauri-plugin-sql) | 学習データ・テンプレ・途中保存を1ファイルで管理 |
| CSVパース | Papa Parse | 文字コード自動判定対応 |
| インストーラ | Tauri内蔵 WiX (msi) | Windows標準形式 |
| スタイリング | TailwindCSS | 軽量・Excel風UIの作り込みやすさ |

## 6. コード署名方針

- **MVP〜初期配布は未署名で配布**
- 顧問先のPCで SmartScreen 警告が出る可能性があるため、マニュアルに「詳細情報 → 実行」の操作手順を記載
- 顧問先数が増えてサポート負担が発生してきた段階で EV 証明書取得を検討

参考: 未署名配布時の挙動
- ブラウザ/メール/クラウド経由でDLした場合、Mark of the Web により SmartScreen 警告が出る
- USB等のローカル配布なら警告が出ないこともある

---

## 7. スコープ外（やらないこと）

- 摘要以外の項目の検出・修正
- 複数顧問先の同時管理（1インストール = 1顧問先）
- 複数CSVの同時編集（タブ機能等）
- データ暗号化
- クラウド同期
- Mac/Linux対応
- 振込指図書生成、会計ソフトとの直接連携

---

## 8. 残課題

- 取引先サジェストの精度（金額＋日付以外の補助キー検討）
- 大量CSV（数万行）でのパフォーマンス検証
- 顧問先初回セットアップ時のオンボーディングUX
